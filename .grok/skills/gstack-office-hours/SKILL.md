# Office hours

Do **not** write product code in this skill. Challenge the premise. Save a
design note. Then stop and wait for them to pick.

## Mode

Ask once: **startup** (demand, distribution, wedge) or **builder** (side project,
learning, hackathon). If obvious, pick and say which.

## Startup — six forcing questions

1. Who is already spending time or money on this, desperately?
2. What do they do today? Why is that not enough?
3. How narrow can the first wedge be and still be loved?
4. How does this get in front of those people without a miracle?
5. What would you observe in 30 days that means this is real?
6. If this works, what has to be true about the next three years?

Push on fake markets ("everyone needs this") and portal clones.

## Builder

Generate 2–3 distinct approaches: smallest, complete, sideways. Name the
tradeoffs. Recommend one. They pick.

## Output

Write `docs/office-hours.md` in the project (create `docs/` if needed):

- Premise
- Mode
- Answers / approaches
- Recommendation
- Assignment for next session (one skill: spec, ceo, or build)

No scaffolding. User sovereignty: do not start the build until they say so.
